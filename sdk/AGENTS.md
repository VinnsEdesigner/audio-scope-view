## DSP core: C++ → WASM → TS (architecture migration, Step 3 complete)
- **Single source of truth:** the DSP core is C++ in `sdk/dsp/` (`audioscope::dsp` namespace). The Rust FFI (`rust/src/infrastructure/dsp_ffi.rs`) and the WASM/TS wrapper (`packages/dsp-wasm/`) both call the SAME flat C ABI in `sdk/bindings/ffi/audioscope_ffi.{h,cpp}`. There is no duplicate TS FFT anymore — `packages/dsp-wasm/src/audioscope-dsp.ts` is a thin memory-marshalling wrapper, not a reimplementation.
- **C ABI (the FFI seam):** `audioscope_ffi.h` declares `as_*` C structs + `as_*` free functions. Composite returns (spectrum, harmonics, spectrogram, waveform analysis, compressed waveform) are returned as **malloc'd struct pointers** with inner arrays; callers read fields at fixed offsets then call the matching `as_*_free` (frees inner arrays) + `em_free`/`free` (frees the holder). Array returns (magnitudes, triggered window, generated waveform, resampled) use the **malloc'd pointer + `int* out_len`** pattern — robust across all binding runtimes.
- **WASM build (`sdk/wasm/`):** `emscripten_main.cpp` has `EMSCRIPTEN_KEEPALIVE` `extern "C"` wrappers (`em_*`) over the C ABI. CRITICAL: must be `extern "C"` or symbols get C++-mangled and the JS `EXPORTED_FUNCTIONS` list (by C name) fails to link. `CMakeLists.txt` links the `audioscope_dsp`/`audioscope_common` static libs with `--whole-archive` (KEEPALIVE exports have no C++ callers and would be stripped otherwise). emcc flags: `-O3 -msimd128 -msse -msse2 MODULARIZE=1 EXPORT_ES6=1 EXPORT_NAME=AudioScopeDspModule ALLOW_MEMORY_GROWTH=1`. `build.sh` runs emcmake/emmake and stages `audioscope.{js,wasm}` to `packages/dsp-wasm/dist/`.
- **WASM i64 marshalling gotcha:** Emscripten `ccall`/`cwrap` infers arg types from the C signature; `long long`/`int64_t` args require BigInt at the JS call site (`Cannot convert 0 to a BigInt`). The `em_*` wrappers use **i32** for `holdoff` (samples) and `start_time_ms` (fits in i32: ~24 days) and cast to i64 internally — the underlying `as_*` ABI keeps int64_t. Do not reintroduce `long long` in `em_*` signatures.
- **EXPORTED_FUNCTIONS vs EXPORTED_RUNTIME_METHODS:** `_malloc`/`_free` belong in `EXPORTED_FUNCTIONS` (compiled exports), NOT `EXPORTED_RUNTIME_METHODS` (JS-side helpers like `ccall`/`getValue`/`HEAPF32`). Putting them in the latter causes "undefined exported symbol: _malloc".
- **Vendored LZ4:** `sdk/dsp/third_party/lz4/` (LZ4 1.10.0 sources) makes portable targets self-contained. `compression.cpp` only uses `LZ4_compress_default`, `LZ4_compress`, `LZ4_decompress_safe`. The `audioscope_lz4_vendored` CMake target compiles only `lz4.c`. `AUDIOSCOPE_USE_VENDORED_LZ4=ON` (set in the `wasm` CMake preset) selects it; native builds use system lz4.
- **`packages/dsp-wasm/` package:** `AudioScopeDsp` class is the browser/worklet analog of the Rust `dsp_ffi.rs`. Memory model: alloc f32 into HEAPF32 → call `em_*` → copy result out via `HEAPF32.slice` → free. Struct field offsets are hardcoded constants (wasm32, natural alignment) in `audioscope-dsp.ts` matching `audioscope_ffi.h`. Two scratch pointers (`tmpLenPtr`, `tmpMagPtr`) are reused across calls to avoid per-call malloc churn. The generated `audioscope.js`/`.wasm` are gitignored (regenerated by `build:wasm`); the hand-written `dist/audioscope.d.ts` is force-added so typecheck works in a fresh checkout.
- **Build config:** root `package.json` has `build:wasm` (= `bash sdk/wasm/build.sh`), `build:sdk`, `test:sdk` (ctest), `test:wasm` (vitest). `build` depends on `build:wasm`. `turbo.json` declares `build:wasm`/`build:sdk`/`test:sdk`/`test` tasks (the vitest `test` task depends on `build:wasm`). The stale `dev:web`/`dev:mobile` scripts were removed.
- **Testing parity across all three bindings:** native C++ SDK tests (ctest, 36 tests in `sdk/`), WASM vitest (`packages/dsp-wasm/test/dsp-wasm.test.ts`, 12 tests — loads WASM in Node, FFT on a 440 Hz sine, asserts peak; covers measurements, harmonics, LZ4 round-trip, trigger, generators), and Rust FFI tests (`cargo test`, 31 tests in `rust/`). All three exercise the same C++ core, so parity is provable.
- **Toolchain versions (sandbox):** cmake 3.31.6, ninja 1.12.1, emsdk 6.0.6 (emcc), node v22.23.2, pnpm 11.15.1. emsdk at `/home/openhands/emsdk` (run `source $HOME/emsdk/emsdk_env.sh` before any `cmake --preset wasm`/emcc command).
- **Branch:** `feat/cpp-dsp-core-rust-ffi-migration`. Step 1+2 = commit `437b7f7` (C++ core + Rust FFI bridge + Rust DSP files deleted). Step 3 = commit `2694101` (WASM build + dsp-wasm TS package + root build config). Remote: `github.com/VinnsEdesigner/audio-scope-view`.

## Linux/Windows native audio bindings (STEP 6 — §A.4, DONE)
- **Feature:** The ALSA + PulseAudio (Linux) and WASAPI (Windows) `AudioBinding` implementations — the desktop analog of Android's `oboe_capture.cpp`. All four platforms now implement the SAME `audioscope::bindings::AudioBinding` interface (enumerate/start/stop/read/is_capturing), so a native desktop client links the platform-appropriate target and reaches the shared C++ DSP core without a second capture path. The Rust server's `cpal` capture stays as-is (server-hosted `capture` mutation) — this step is for a desktop *client* app, per ARCHITECTURE_IMPLEMENTATION_SPEC §4 step 6.
- **New files:**
  - `sdk/bindings/linux/alsa_binding.cpp` — `AlsaCapture` via `snd_pcm_*`. `snd_device_name_hint` enumerates capture PCMs (IOID "Input"); `start_capture` opens the PCM, prefers `SND_PCM_FORMAT_FLOAT_LE`, falls back to `S16_LE` (normalized via `convert_samples_to_f32`), and reads on a background thread into a mutex-guarded `FloatRing`. Underruns recovered with `snd_pcm_recover`. Factory: `audioscope_linux_alsa_binding_create/destroy`.
  - `sdk/bindings/linux/pulse_binding.cpp` — `PulseCapture` via `pa_simple_*` (the simple blocking API). Exposes `default` + `auto_null.monitor` (headless loopback). `pa_sample_spec` requests `PA_SAMPLE_FLOAT32LE`, retries `PA_SAMPLE_S16LE`. Factory: `audioscope_linux_pulse_binding_create/destroy`.
  - `sdk/bindings/windows/wasapi_binding.cpp` — `WasapiCapture` via `IMMDeviceEnumerator` + `IAudioCaptureClient`. COM apartment initialized RAII-style (`CoInitializeEx`/`CoUninitialize`); `#ifdef _WIN32`-guarded so the file is a no-op translation unit on non-Windows hosts (CMake only adds the subdirectory under `if(WIN32)`). Coerces to mono float32 `WAVEFORMATEXTENSIBLE`, falls back to the device mix format, downmixes multi-channel to mono by averaging. Factory: `audioscope_windows_wasapi_binding_create/destroy`.
  - `sdk/bindings/linux/CMakeLists.txt` — `audioscope_bindings_linux_alsa` (links `pkg-config alsa`), `audioscope_bindings_linux_pulse` (links `pkg-config libpulse-simple` — **not** `libpulse`; `pa_simple_*` lives in the separate `-lpulse-simple`), and an `INTERFACE` aggregate `audioscope_bindings_linux` so a host links one name.
  - `sdk/bindings/windows/CMakeLists.txt` — `audioscope_bindings_windows` (links `ole32` for `CoInitialize`).
  - `sdk/tests/test_bindings.cpp` — GoogleTest smoke tests: factory returns non-null, `enumerate_devices()` non-empty with a flagged default, `read_samples` is a safe no-op before `start_capture`, `start_capture("__nonexistent_device__")` returns false (no stream opened — **no real hardware needed**), `stop_capture()` idempotent. Parametrized over alsa + pulse.
- **CMake wiring:** `sdk/CMakeLists.txt` now gates the binding subdirectories by host OS — `if(UNIX AND NOT APPLE) add_subdirectory(bindings/linux)` and `if(WIN32) add_subdirectory(bindings/windows)`. The Android binding is NOT built here (it's driven by the Gradle NDK build via `sdk/bindings/android/CMakeLists.txt` directly). New `linux-bindings` CMake preset (`AUDIOSCOPE_BUILD_BINDINGS=ON`) + matching build/test presets. `test_bindings` is only added to the test list when `AUDIOSCOPE_BUILD_BINDINGS AND UNIX AND NOT APPLE`.

## ESP32 firmware + bare-USB host binding (STEP 9 — §A.6, DONE)
- **Design decision (overrides ARCHITECTURE.md's earlier UAC plan):** the ESP32 presents a **custom vendor-class USB device**, NOT a USB Audio Class device. The host talks to the processor **directly via libusb**, bypassing the OS audio stack (ALSA/WASAPI/CoreAudio/Oboe). User explicitly wanted "bare" / no usual audio paths. Tradeoff recorded: loses plug-and-play with arbitrary DAWs/recorders (needs the audioscope host or any libusb client); gains direct processor control, a real control surface (gain/rate/channels/timebase/trigger/vscale/coupling) UAC lacks, lower latency, no OS audio processing. Rationale + wire-protocol spec in `docs/ESP32_USB_PROTOCOL.md`.
- **It's a real oscilloscope, not just an audio capture:** raw ADC acquisition at the device's actual bandwidth (host queries `GET_BANDWIDTH` → real PCM1802 datasheet limits: 96 kHz max rate, 77 kHz analog BW, 24-bit, 3200 mV p-p range; effective BW = min(adc_max_rate/2, analog_bw_hz)); PWM/signal generation output (`generator.c`, LEDC hardware PWM up to 5 MHz for square/DC + sine/tri/saw via DAC); configurable scope settings (`SET_TIMEBASE`, `SET_TRIGGER`, `SET_VSCALE`, `SET_COUPLING`).
- **New files — firmware (`sdk/firmware/esp32/`, ESP-IDF v5.4 + vendored TinyUSB):**
  - `CMakeLists.txt` (top-level ESP-IDF project; `EXTRA_COMPONENT_DIRS` points at the vendored `components/tinyusb`; `include($ENV{IDF_PATH}/.../project.cmake OPTIONAL)` so it browses in a plain CMake editor without IDF), `partitions.csv`, `sdkconfig.defaults` (USB OTG + I2S + PSRAM; NO `CONFIG_ESP_TINYUSB` kconfig — that's the managed-component wrapper we don't use), `idf_component.yml` (no deps — TinyUSB vendored locally).
  - `components/tinyusb/` — vendored real TinyUSB (upstream `hathach/tinyusb` master, Synopsys DWC2 DCD for the S3's native USB OTG). `tusb_config.h` enables only the vendor class (CDC/MSC/HID/AUDIO/MIDI all 0). `CMakeLists.txt` compiles `tusb.c`/`tusb_fifo.c`/`vendor_device.c`/`dcd_dwc2.c`/`dwc2_common.c` and defines `CFG_TUSB_MCU=OPT_MCU_ESP32S3`, `CFG_TUSB_OS=OPT_OS_FREERTOS`, `CFG_TUSB_OS_INC_PATH=freertos/` (PUBLIC — ESP-IDF's FreeRTOS headers live under `include/freertos/`).
  - `main/main.c` — `app_main`: init USB → codec → ring → control/stream/generator tasks.
  - `main/usb_descriptors.c` — TinyUSB device + config descriptors (**vendor class**, bulk IN 0x81 + OUT 0x01, `TUD_VENDOR_DESCRIPTOR`; NOT UAC). VID 0x1209 / PID 0xA500 (pid.codes community; overridable via `-D`).
  - `main/usb_device.c/.h` — TinyUSB vendor-class callbacks (`tud_vendor_control_xfer_cb` → `tud_control_status`; `tud_vendor_rx_cb`/`tx_cb` with `uint32_t` lengths; `usb_device_send_response` → `tud_vendor_write`).
  - `main/codec.c/.h` — I2S codec driver via ESP-IDF `driver/i2s_std.h` (`i2s_channel_init_std_mode`); PCM1802 default (real 24-bit ADC, `codec_bandwidth()` returns datasheet specs), UDA1334A/WM8731 clean swap-point. On-chip ADC explicitly avoided (too low-rate/noisy).
  - `main/generator.c/.h` — waveform generator (LEDC hardware PWM: square/DC up to `AS_USB_GEN_MAX_FREQ_HZ`=5 MHz, 12-bit duty; sine/tri/saw via DAC). `generator_start/stop`.
  - `main/ring_buffer.c/.h` — FreeRTOS ring between DMA-read task and USB bulk-IN task.
  - `main/stream_task.c/.h` — codec → ring → bulk-IN pump (frames the stream with `as_usb_stream_header`).
  - `main/control_task.c/.h` — host command dispatcher (GET_INFO/GET_BANDWIDTH/START/STOP/SET_RATE/SET_GAIN/SET_CHANNELS/SET_TIMEBASE/SET_TRIGGER/SET_VSCALE/SET_COUPLING/GEN_*; owns the streaming flag).
  - `main/board_config.h` — pin map (I2S BCLK=4/LRCK=5/DOUT=6, PCM1802 wiring) + USB endpoint config + `AUDIOSCOPE_CODEC_ID`.
  - `README.md` — wiring, codec choice, analog front-end, build/flash.
- **New files — host binding (`sdk/bindings/usb/`, libusb-1.0):**
