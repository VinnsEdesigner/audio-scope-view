## Android audio input device enumeration (STEP 5 — C++ device enumeration, DONE)
- **Feature:** Enumerate the OS's connected audio input devices **by name** (builtin mic, wired headset, USB mics, Bluetooth), done **entirely in C++** — the user explicitly wanted to avoid Kotlin/Java-layer APIs where possible. The Kotlin side only passes the `ReactApplicationContext` through; no Java enumeration logic.
- **Two C++ sources merged** (new file `sdk/bindings/android/device_enumeration.{cpp,h}`):
  1. `android.media.AudioManager.getDevices(GET_DEVICES_INPUTS)` driven via JNI **from C++** (`FindClass`/`GetMethodID`/`CallObjectMethod` on the Context → getSystemService("audio") → getDevices(3)). Iterates `AudioDeviceInfo` for `getId()` (the Oboe-routable id), `getName()`, `getType()` (mapped to `builtin-mic`/`wired-headset`/`usb-device`/`usb-headset`/`bluetooth-sco`/`bluetooth-a2dp`/`dock`/`hdmi`/...), `getProductName()`, `isSource()`, `getSampleRates()`, `getChannelCounts()`. Every JNI call is followed by `ExceptionCheck`/`ExceptionClear` (a ROM-level exception would otherwise abort).
  2. Pure-C++ parse of `/proc/asound/cards` + `/proc/asound/cardN/id` + `/proc/asound/cardN/usbid` (and `/sys/class/sound/cardN/device/modalias` fallback) for the ALSA card short name + USB **vendor/product ids**, which the framework frequently does not expose (`productName` is often null on USB mics). Merged into the framework list by case-insensitive name match.
- **Return shape:** a JSON array string (parsed by the TS bridge) — `[{"id":"12","name":"...","type":"usb-device","productName":"...","isDefault":false,"sampleRates":[...],"channels":[...],"usbVendor":7224,"usbProduct":3164,"alsaCard":1}, ...]`. The first device is flagged `isDefault`.
