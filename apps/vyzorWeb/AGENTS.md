
## Frontend (web app) gotchas
- The home recordings list reads `useRecentRecordings` (query `GET_RECENT_RECORDINGS`), NOT `useRecordings` (`GET_RECORDINGS`). Any recording mutation (pin/rename/delete/create) must refetch `GET_RECENT_RECORDINGS` too, or the home list shows stale pin/rename/delete state. See `RECENT_RECORDINGS_REFETCH` in `apps/vyzorWeb/src/hooks/use-recordings.ts`.
- Main scroll container is `apps/vyzorWeb/src/root.tsx:55` (`overflow-y-auto`), which clips absolutely-positioned dropdowns that extend beyond it. `position: fixed` dialogs (session-settings, create-session) escape this, but their downward dropdowns can still run off the viewport on mobile — `InlineSelect` flips up / clamps `maxHeight` to available space to handle this.
- More-menu / popover z-index: use `z-50` (sticky header is `z-30`). The recordings more-menu previously used `z-10` and rendered behind later rows.
- GraphQL fragments/queries were verified to match the Rust schema via introspection (SESSION_FIELDS, RECORDING_FIELDS, RECORDING_SUMMARY_FIELDS, SessionWithStatusFields, all wrapper result types).

## Docker / Client-Server Connection (IMPORTANT)
- The deployed image bundles a static-server (Node, port 3000) that serves the SPA and reverse-proxies `/graphql` and `/ws` to the Rust backend (127.0.0.1:8080 inside the container). So the browser must use **relative** endpoints (`/graphql`, `/ws`), NOT absolute `ws://localhost:8080/...` URLs — the browser's `localhost` is not the container's localhost, so absolute URLs break in Docker/remote deploys.
- `packages/api-client/src/config.ts` `DEFAULT_CONFIG`: `graphqlEndpoint: "/graphql"`, `websocketEndpoint: "/ws"`. `apps/vyzorWeb/src/hooks/use-waveform-stream.ts` builds the WS URL from `location.host` + `/ws`. `.env.example` and `render.yaml` set `VITE_WEBSOCKET_ENDPOINT=/ws`.
- `VITE_*` env vars are baked into the frontend bundle at **build** time (Vite), not read at runtime. A deployed image with stale/empty build-time env will be broken regardless of runtime env — rebuild the image to pick up new values.
- **Image freshness matters:** the ghcr image must be rebuilt from current source after client-side changes. A stale image renders the UI but the Apollo client may silently fail to fire queries (no POST /graphql in server logs). Always rebuild + redeploy after frontend fixes.
- Run locally: `docker run -p 3000:3000 -p 8080:8080 -e BOOTSTRAP_KEY="$(openssl rand -hex 32)" ghcr.io/vinnsedesigner/audio-scope-view:latest`. Health: `curl http://localhost:3000/health`.
- Dev frontend (no Docker): `pnpm --filter @audio-scope-view/vyzor-web dev` (add a `server.proxy` in vite.config.ts pointing `/graphql`+`/ws` at the backend port to test against a running server).

## Apollo Error Toast Sanitization
- `apps/vyzorWeb/src/lib/format-error.ts` `formatError(error)` is the single entry point for all user-facing toasts. It strips `http(s)://` and `ws(s)://` URLs from messages, collapses whitespace, and maps `Failed to fetch` / `NetworkError` / `Load failed` to `"Network error: unable to reach the server. Check your connection and try again."` so internal endpoints (`http://127.0.0.1:8080/graphql`) never leak to the UI.
- `packages/api-client/src/audioScopeView/graphql/client.ts` `sanitizeErrorMessage` does the same for Apollo `onError` link messages.

## Web app wiring: dsp-wasm + WebGL2 renderer (architecture migration, Steps 4–5 complete)
- **Single DSP source of truth in the browser:** the web app no longer has a duplicate TS FFT. `apps/vyzorWeb/src/lib/scope-dsp.ts` (radix-2 FFT, `computeSpectrum`, `toDecibels`, `triggeredWindow`, `findTriggerIndex`, `resampleTo`) is **deleted**. All DSP flows through `@audio-scope-view/dsp-wasm` (the C++ core compiled to WASM). The web app's `AudioScopeDsp` calls are the browser/worklet analog of the Rust `dsp_ffi.rs` — same C ABI, same core.
- **Singleton loader (`apps/vyzorWeb/src/lib/dsp-loader.ts`):** `ensureDsp()` (async, kicks off + awaits the WASM load, memoized, failure-tolerant → returns null) and `getDsp()` (sync, returns the loaded instance or null). Shared by `scope-canvas.tsx`, `use-audio-analyzer.ts`, `use-waveform-generator.ts`, `measurements-dialog.tsx`. The WASM module is expensive to instantiate (fetch + compile); it must load exactly once. Hot-path callers (rAF draw loop, capture tick) read `getDsp()` and degrade gracefully (free-run / inline fallback) until loaded — the UI never blocks on module load.
- **Consumers wired:** (1) `scope-canvas.tsx` — spectrum is drawn from a precomputed WASM `Spectrum` (dB magnitudes + frequencies, no `toDecibels` step); `triggeredWindow` calls `dsp.triggeredWindow` (returns `Float32Array | null`); `ensureDsp()` on mount. (2) `use-audio-analyzer.ts` — RMS/peak/frequency via `dsp.computeRms`/`findPeakAmplitude`/`estimateDominantFrequency` (with tiny inline TS fallbacks pre-load). (3) `measurements-dialog.tsx` — Vpp/RMS/DC-offset/frequency via the WASM core. (4) `use-waveform-generator.ts` — the old TS `generateSample` synthesizer in `use-mock-audio-analyzer.ts` is replaced by `dsp.generateWaveform` (C++ sine/square/saw/triangle/noise generators); the generator hook drives the new `WaveformGeneratorDialog` (Activity icon in the top bar), which replaced the non-functioning "test mode".
- **WASM asset serving:** `vite.config.ts` adds `optimizeDeps.include: ["@audio-scope-view/dsp-wasm"]` and `assetsInclude: ["**/*.wasm"]`; the production build emits `dist/client/assets/audioscope-*.wasm` (42K) as a referenced asset. `scripts/static-server.cjs` adds `.wasm → application/wasm` to its MIME map (otherwise the browser refuses to compile/stream the module).
- **Type compatibility:** the ui-store's `triggerEdge: "rising" | "falling" | "auto"` is structurally identical to the WASM `TriggerEdge`, so no adapter is needed. `frame` in `scope-canvas.tsx` is `ArrayLike<number>` (the WASM `triggeredWindow` returns `Float32Array`; held frames are `number[]`), so the `for...of` loop was converted to an index loop (`ArrayLike` is not `Iterable` in strict TS).
- **Root `test:sdk` script bug (fixed):** the script did `cd sdk/build/linux && ctest --preset linux`, but `CTestPresets.json` lives in `sdk/`, so ctest could not find the presets from the build subdir. Fixed to `(cd sdk && ctest --preset linux)`.
- **WebGL2 renderer (`src/lib/webgl/`, Step 5 / spec §C.1 — DONE):** the Canvas2D path in `scope-canvas.tsx` is **fully removed** (no `getContext("2d")` remains). Raw WebGL2 is used directly — **no `regl`/`gl-matrix` deps were added** (the spec offered "regl or raw WebGL2 — decide"; raw was chosen, with a hand-rolled `mat4.ts` for ortho/identity). Renderers (all under `src/lib/webgl/`, barrel `index.ts`): `ScopeRenderer` (instanced line trace), `SpectrumRenderer` (spectrum bars), `SpectrogramRenderer` (2D waterfall texture), plus two the spec didn't enumerate — `GlyphRenderer` (SDF text for labels/readouts) and `OverlayRenderer` (grid/cursors/markers). Shaders: `shaders/{line,spectrum,spectrogram,glyph}.{vert,frag}` + `shaders/index.ts`. `GLContext.from(canvas)` acquires one WebGL2 context per canvas and owns the program cache; `scope-canvas.tsx` instantiates a `RendererBundle` of all five renderers sharing it. View selection: `ui-store.ts` `ScopeView = "time" | "spectrum" | "spectrogram"` (spectrogram is new in this step).
- **WebGL2 fallback decision (spec hazard #11 — resolved as: no Canvas2D fallback):** `GLContext.from()` returns `null` when WebGL2 is unavailable; `scope-canvas.tsx` then `console.warn`s and renders an empty surface (no Canvas2D fallback path). WebGL2 is a hard runtime requirement (Chrome/Edge/Firefox/Safari post-2020 all provide it). Do not reintroduce a Canvas2D path.
- **Waveform Generator (replaces "test mode"):** `test-mode-icon.tsx` + the old test-mode UI are deleted; `WaveformGeneratorDialog` (`components/scope/waveform-generator-dialog.tsx`) + `useWaveformGenerator` (`hooks/use-waveform-generator.ts`) feed the scope from the C++ DSP core via WASM (`dsp.generateWaveform`), so rendering/measurements can be verified without a live audio input. Open the dialog (Activity icon), pick Sine/Square/Sawtooth/Triangle/Noise (+ noise color), and the measurement panel shows expected Vpp/Freq/Win.
- **§C.3 playback worklet repointed to the C++ core (DONE):** `apps/vyzorWeb/src/audio/worklets/audio-streaming-processor.js` no longer just plays PCM chunks — it loads the same WASM `AudioScopeDsp` the live-capture path uses and runs per-block DSP (`_em_compute_magnitudes` + `_em_analyze_waveform`) on the played samples, posting `{type:"frame", magnitudes, analysis, sampleRate}` to the main thread for the WebGL renderer. This unifies the DSP source of truth across live capture and playback. The worklet loads the WASM module by **URL** (the main thread resolves the Vite-hashed `audioscope.js`/`.wasm` URLs via `?url` imports in `use-streaming-playback.ts` and passes them in the `config` message); the worklet can't use a bundler `import` (AudioWorklet global scope, flat public URL). `locateFile` is overridden to point at the binary URL (the default `import.meta.url`-based lookup would resolve relative to the worklet — wrong). DSP load is failure-tolerant: if the module fails to load, audio still plays — only the per-block frames stop (mirrors `dsp-loader`'s degradation). `use-streaming-playback.ts` gained an `onDspFrame` option; the `frame`/`dsp_ready`/`dsp_error` messages are typed in the worklet `.d.ts`. The renderer consumes playback frames with the same shape as live frames.
- **`sdk/common/` completion (spec §A.2 — DONE):** the "future/to be done" comments are gone. `buffer.hpp` now has `PoolAllocator<T>` — a free-list object pool with **stable-address** backing storage (`std::vector<std::unique_ptr<T>>`, so `emplace_back` never invalidates an outstanding pointer) and a lock-free Treiber-stack free list; once warm, `acquire`/`release` touch no heap. `config.hpp`/`config.cpp` now have `from_json`/`to_json` (a tiny dependency-free hand-rolled JSON object parser — `common` stays Layer-1-clean, no nlohmann) + `DspConfig::normalized()` (clamps overlap to [0,1), rounds `fft_size` to next pow2, bounds the spectrogram band to Nyquist, swaps inverted bands) + `parse_window_type`/`window_type_name`. `types.hpp`/new `types.cpp` add `sample_format_size()` + `convert_samples_to_f32()` (S16/S32/F32 → normalized F32, the single normalization path every platform binding calls). **Bug fix while here:** the pre-existing `AudioRingBuffer` had a latent correctness bug — `(w - r) % capacity_` made a full ring indistinguishable from an empty one (so `push` overwrote past capacity and `available()` returned 0 when full). Fixed to use `w - r` (monotonic indices, never wrapped) as the count directly; the modulo is only for the physical slot index. New `sdk/tests/test_common.cpp` (25 tests: ring buffer round-trip/wrap/concurrency, pool reuse/growth/stable-address, JSON parse/round-trip/unknown-keys/malformed, normalization clamps, S16/S32/F32 conversion).
